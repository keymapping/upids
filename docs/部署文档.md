## 2. Docker 基础设施部署

### 2.1 启动数据库服务

```bash
cd d:\java_web\UPIDS\UPIDS
docker-compose up -d
```

### 2.2 服务配置说明

| 服务 | 镜像 | 端口 | 说明 |
|------|------|------|------|
| postgres | postgis/postgis:14-3.3 | 5432 | PostgreSQL + PostGIS 空间数据库 |
| redis | redis:7-alpine | 6379 | 缓存服务 |
| pgadmin | dpage/pgadmin4:latest | 5050 | 数据库管理工具 |

### 2.3 数据持久化

```
./postgres-data/  # PostgreSQL 数据目录
./redis-data/     # Redis 数据目录
./pgadmin-data/   # pgAdmin 配置目录
```

### 2.4 常用 Docker 命令

```bash
# 查看服务状态
docker-compose ps

# 查看日志
docker-compose logs -f
docker-compose logs -f postgres

# 停止服务
docker-compose down

# 重启服务
docker-compose restart

# 删除容器（保留数据）
docker-compose rm
```

## 3. 数据库初始化

### 3.1 等待数据库就绪

首次启动 PostgreSQL 需等待约 30 秒初始化完成，可通过以下命令验证：

```bash
docker exec -it upids-postgres pg_isready -U upids_admin -d upids
```

### 3.2 执行初始化脚本

```bash
# 方式一：自动执行（docker-compose 已配置）
# sql/init.sql 会自动挂载到 /docker-entrypoint-initdb.d/

# 方式二：手动执行
docker exec -i upids-postgres psql -U upids_admin -d upids <<EOF
\i /docker-entrypoint-initdb.d/00_init.sql
\q
EOF

# 方式三：通过 pgAdmin 执行
# 访问 http://localhost:5050
# 登录：admin@upids.com / admin123
# 依次执行：sql/init.sql → sql/schema.sql → sql/init_data.sql
```

### 3.3 数据库连接信息

| 配置项 | 值 |
|--------|-----|
| Host | localhost |
| Port | 5432 |
| Database | upids |
| Username | upids_admin |
| Password | upids_admin_123 |
| Schema | public |

## 4. 后端服务部署

### 4.1 配置文件

**文件路径**: `backend/src/main/resources/application.yml`

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| server.port | 8080 | 后端服务端口 |
| spring.datasource.url | jdbc:postgresql://localhost:5432/upids | 数据库连接 |
| spring.datasource.username | upids_admin | 数据库用户名 |

## 5. 前端服务部署

### 5.1 开发模式启动

```bash
cd d:\java_web\UPIDS\UPIDS\frontend

npm run dev
```

### 5.2 生产构建

```bash
cd d:\java_web\UPIDS\UPIDS\frontend
npm install
npm run build
```

构建产物位于 `dist/` 目录。

### 5.3 Nginx 部署（生产环境）

**配置文件**: `/etc/nginx/conf.d/upids.conf`

```nginx
server {
    listen 80;
    server_name your-domain.com;

    # 前端静态文件
    location / {
        root /path/to/frontend/dist;
        index index.html;
        try_files $uri $uri/ /index.html;
    }

    # API 反向代理
    location /api/ {
        proxy_pass http://localhost:8080/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # 文件上传服务
    location /uploads/ {
        alias /path/to/backend/uploads/;
        expires 30d;
    }

    # 错误页面
    error_page 404 /index.html;
}
```

### 5.4 环境变量配置

**文件路径**: `frontend/.env.development`（开发环境）

```env
VITE_API_BASE_URL=http://localhost:8080
```

**文件路径**: `frontend/.env.production`（生产环境）

```env
VITE_API_BASE_URL=https://your-domain.com
```

## 7. 生产环境配置

### 7.1 环境变量说明

后端支持通过环境变量覆盖配置：

| 环境变量 | 对应配置 | 说明 |
|----------|----------|------|
| DB_HOST | spring.datasource.url | 数据库地址 |
| DB_PORT | spring.datasource.url | 数据库端口 |
| DB_NAME | spring.datasource.url | 数据库名称 |
| DB_USER | spring.datasource.username | 数据库用户名 |
| DB_PASSWORD | spring.datasource.password | 数据库密码 |
| REDIS_HOST | spring.redis.host | Redis 地址 |
| REDIS_PORT | spring.redis.port | Redis 端口 |
| JWT_SECRET | upids.jwt.secret | JWT 密钥（**必须修改**） |
| PYTHON_URL | upids.python.base-url | Python 服务地址 |
| UPLOAD_PATH | upids.upload.path | 上传目录 |

### 7.2 启动脚本示例

**start.sh**（Linux 生产环境）

```bash
#!/bin/bash

export JAVA_HOME=/usr/lib/jvm/java-17-openjdk
export PATH=$JAVA_HOME/bin:$PATH

export DB_HOST=localhost
export DB_PORT=5432
export DB_NAME=upids
export DB_USER=upids_admin
export DB_PASSWORD=your-secure-password
export JWT_SECRET=your-256-bit-secret-key
export PYTHON_URL=http://localhost:5000

cd /opt/upids/backend
nohup java -jar upids-backend-1.0.0.jar > /var/log/upids-backend.log 2>&1 &

cd /opt/upids/python-service
nohup gunicorn -w 4 -b 0.0.0.0:5000 app:app > /var/log/upids-python.log 2>&1 &

echo "UPIDS services started."
```

### 7.3 防火墙配置（Linux）

```bash
# 开放端口
sudo firewall-cmd --permanent --add-port=80/tcp
sudo firewall-cmd --permanent --add-port=8080/tcp
sudo firewall-cmd --permanent --add-port=5000/tcp
sudo firewall-cmd --permanent --add-port=5432/tcp
sudo firewall-cmd --permanent --add-port=6379/tcp

# 重启防火墙
sudo firewall-cmd --reload
```

### 7.4 SSL 证书配置（Nginx）

```nginx
server {
    listen 443 ssl;
    server_name your-domain.com;

    ssl_certificate /etc/nginx/ssl/fullchain.pem;
    ssl_certificate_key /etc/nginx/ssl/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;

    location / {
        root /path/to/frontend/dist;
        index index.html;
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://localhost:8080/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;
    }
}

server {
    listen 80;
    server_name your-domain.com;
    return 301 https://$host$request_uri;
}
```

## 9. 常见问题排查

### 9.1 Java 版本问题

**现象**: Maven 编译报错，提示 Java 版本不兼容

**解决方案**:

```bash
# 检查 Java 版本
java -version

# 设置正确的 JAVA_HOME
export JAVA_HOME=/d/java17
export PATH=/d/java17/bin:$PATH

# 清理旧编译产物
mvn clean

# 重新编译
mvn spring-boot:run
```

### 9.2 端口冲突

**现象**: 启动时提示端口被占用

**解决方案**:

```powershell
# Windows：查找占用端口的进程
netstat -ano | findstr :8080

# 终止进程（替换PID）
taskkill /F /PID 12345
```

```bash
# Linux：查找占用端口的进程
lsof -i :8080

# 终止进程
kill -9 12345
```

### 9.3 Spring Boot DevTools 进程残留

**现象**: 多次启动后端口被占用，找不到进程

**解决方案**:

```powershell
# 查找所有 Java 进程
tasklist | findstr java

# 终止所有 Java 进程
taskkill /F /IM java.exe
```

### 9.4 数据库连接失败

**现象**: 后端启动报错，无法连接数据库

**排查步骤**:

1. 确认 Docker 服务已启动：`docker-compose ps`
2. 确认 PostgreSQL 健康检查通过：`docker exec upids-postgres pg_isready`
3. 确认数据库配置正确（用户名、密码、端口）
4. 检查防火墙是否阻止了 5432 端口

### 9.5 前端 API 请求失败

**现象**: 前端无法访问后端接口，报 404/502 错误

**排查步骤**:

1. 确认后端服务已启动：`curl http://localhost:8080/api/auth/me`
2. 确认前端配置的 API 地址正确：检查 `.env.development`
3. 检查跨域配置：后端是否配置了正确的 CORS
4. 检查 Nginx 反向代理配置

### 9.6 Python 服务启动失败

**现象**: `python app.py` 报错

**排查步骤**:

1. 确认 Python 版本：`python --version`（需 3.10+）
2. 重新安装依赖：`pip install -r requirements.txt`
3. 检查模型文件是否存在
4. 检查端口 5000 是否被占用
