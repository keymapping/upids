# 一、实施目标

为了保证团队开发效率，减少数据库同步成本，本项目采用**集中式数据库共享开发模式**。

数据库仅部署一份，由一名组员（建议后端负责人）负责维护，所有成员通过局域网连接同一数据库进行开发。

实现目标：

- 一套数据库（PostgreSQL + PostGIS）
- 多人共同开发
- 数据实时同步
- 无需频繁导入导出 SQL
- 满足课程开发需求（8 张表、空间数据、≥1 万条模拟数据）

必须启用以下扩展：

```sql
CREATE EXTENSION IF NOT EXISTS postgis;
CREATE EXTENSION IF NOT EXISTS postgis_topology;
CREATE EXTENSION IF NOT EXISTS fuzzystrmatch;
CREATE EXTENSION IF NOT EXISTS postgis_tiger_geocoder;
```

## 5.3 空间坐标系

统一使用 **WGS84（EPSG:4326）** 坐标系。

空间字段类型：

| 类型                         | 用途     | 示例                       |
| ---------------------------- | -------- | -------------------------- |
| `GEOMETRY(LineString, 4326)` | 管线坐标 | `pipeline.geo_coordinates` |
| `GEOMETRY(Point, 4326)`      | 缺陷位置 | `defect.location`          |

# 六、Docker Compose

## 6.1 目录结构

```
UPIDS/
├── docker-compose.yml       ← 根目录
├── sql/                     ← SQL 脚本目录
│   ├── init.sql             ← 初始化脚本（含 PostGIS 扩展）
│   ├── schema.sql           ← 表结构 DDL
│   ├── init_data.sql        ← 初始数据（admin 账号）
│   └── migrations/          ← 版本化迁移脚本
├── backend/
├── frontend/
├── python-service/
├── docs/
└── README.md
```

## 6.2 docker-compose.yml

```yaml
version: '3.8'

services:
  postgres:
    image: postgis/postgis:14-3.3
    container_name: upids-postgres
    environment:
      POSTGRES_DB: upids
      POSTGRES_USER: upids_admin
      POSTGRES_PASSWORD: upids_admin_123
    ports:
      - '5432:5432'
    volumes:
      - postgres_data:/var/lib/postgresql/data
      - ./sql/init.sql:/docker-entrypoint-initdb.d/00_init.sql
      - ./sql/schema.sql:/docker-entrypoint-initdb.d/01_schema.sql
      - ./sql/init_data.sql:/docker-entrypoint-initdb.d/02_init_data.sql
    restart: unless-stopped

  redis:
    image: redis:6-alpine
    container_name: upids-redis
    ports:
      - '6379:6379'
    volumes:
      - redis_data:/data
    restart: unless-stopped

  pgadmin:
    image: dpage/pgadmin4
    container_name: upids-pgadmin
    environment:
      PGADMIN_DEFAULT_EMAIL: admin@upids.com
      PGADMIN_DEFAULT_PASSWORD: upids123
    ports:
      - '5050:80'
    volumes:
      - pgadmin_data:/var/lib/pgadmin
    restart: unless-stopped
    depends_on:
      - postgres

volumes:
  postgres_data:
  redis_data:
  pgadmin_data:
```

## 6.3 启动命令

```bash
# 启动所有服务
docker-compose up -d

# 查看日志
docker-compose logs -f

# 停止服务
docker-compose down

# 停止并删除数据卷（谨慎使用）
docker-compose down -v
```

# 七、数据库表结构

## 7.1 表清单

本项目共 **8 张核心表**，全部使用 `snake_case` 命名：

| 序号 | 表名                | 类型归属   | 说明               |
| ---- | ------------------- | ---------- | ------------------ |
| 1    | `sys_user`          | 用户表     | 账号、角色、权限   |
| 2    | `pipeline`          | 数据采集表 | 管线基础与空间数据 |
| 3    | `inspection_record` | 数据采集表 | 巡检图像记录       |
| 4    | `detection_task`    | 业务分析表 | 异步识别任务       |
| 5    | `defect`            | 业务分析表 | 缺陷标注结果       |
| 6    | `alert_record`      | 结果输出表 | 预警记录           |
| 7    | `risk_report`       | 结果输出表 | 风险报告           |
| 8    | `operation_log`     | 日志表     | 操作与审计日志     |

## 7.2 空间索引

必须为空间字段创建 GIST 索引：

```sql
CREATE INDEX idx_pipeline_geom ON pipeline USING GIST(geo_coordinates);
CREATE INDEX idx_defect_geom ON defect USING GIST(location);
```

## 7.3 数据规模要求

| 指标         | 要求           |
| ------------ | -------------- |
| 管线节点     | 1,000 – 20,000 |
| 检测记录     | 1,000 – 5,000  |
| 缺陷记录     | 1,000 – 5,000  |
| 模拟数据总量 | ≥ 10,000 条    |
| 历史记录     | ≥ 3 年         |

# 十四、数据库备份

## 14.1 备份命令

每天开发结束，数据库管理员执行：

```bash
# 备份整个数据库（含空间数据），需使用管理员账号
pg_dump -h 192.168.31.100 -U upids_admin -d upids -f backup_$(date +%Y-%m-%d).sql

# 备份到指定目录
mkdir -p backup
pg_dump -h 192.168.31.100 -U upids_admin -d upids -f backup/backup_$(date +%Y-%m-%d).sql
```

## 14.2 备份文件管理

```
sql/
└── backup/
    ├── backup_2026-06-29.sql
    ├── backup_2026-06-30.sql
    └── ...
```

- 每天生成一份备份
- 每周至少保留一份完整备份
- 备份文件不提交到 Git

## 14.3 数据恢复

```bash
psql -h 192.168.31.100 -U upids_admin -d upids -f backup/backup_2026-06-29.sql
```

# 十七、数据库权限

## 17.1 账号配置

建议建立两个账户：

| 账号          | 权限                 | 使用人员     |
| ------------- | -------------------- | ------------ |
| `upids`       | 读写权限（日常开发） | 所有开发人员 |
| `upids_admin` | 管理员权限（DDL）    | 数据库管理员 |

## 17.2 权限设置

管理员账号 `upids_admin` 由 Docker Compose 初始化时自动创建（拥有 SUPERUSER 权限）。

开发账号 `upids` 在 `sql/init.sql` 中创建：

```sql
-- 创建开发账号（受限权限）
CREATE USER upids WITH PASSWORD 'upids123';
GRANT CONNECT ON DATABASE upids TO upids;
GRANT USAGE ON SCHEMA public TO upids;
GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO upids;
GRANT EXECUTE ON ALL FUNCTIONS IN SCHEMA public TO upids;
GRANT ALL ON ALL SEQUENCES IN SCHEMA public TO upids;
```

# 二十一、最终实施方案

本项目采用 Docker Desktop 部署 **PostgreSQL + PostGIS**、Redis 与 pgAdmin，由数据库管理员统一维护数据库服务，通过局域网向团队成员开放访问。所有成员连接同一数据库进行开发，Spring Boot、Python 与前端项目均在本地运行，通过 GitHub 管理代码，通过 SQL 文件管理数据库结构，通过每日数据库备份保证数据安全。

**技术要点：**

- 数据库：PostgreSQL 14 + PostGIS 3.3（空间数据存储）
- 缓存：Redis 6（GIS 查询缓存）
- 空间坐标系：WGS84（EPSG:4326）
- 表数量：8 张核心表（含用户表、数据采集表、业务分析表、结果输出表、日志表）
- 数据规模：≥10,000 条模拟数据
- 目录结构：`sql/` 存放脚本，`docker-compose.yml` 在根目录

实现统一数据源、统一开发环境、统一数据库版本的团队协作模式。
