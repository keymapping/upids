## 一、Git 协作规范

### 1.1 分支管理

- `main` / `master`：主分支，仅通过 PR 合并，禁止直接推送
- `feature/`：功能分支，如 `feature/pipeline-import`
- `fix/`：修复分支，如 `fix/defect-list-query`
- `refactor/`：重构分支

### 1.2 提交信息规范

```
<type>: <subject>

[type] 可选值：
  feat: 新功能
  fix: 修复 bug
  docs: 文档更新
  style: 代码格式（不影响功能）
  refactor: 重构
  perf: 性能优化
  test: 测试相关
  chore: 构建/工具相关
```

**示例：**

```
feat: 添加管线 GeoJSON 导入功能
fix: 修复任务状态未更新问题
docs: 更新接口文档
refactor: 重构缺陷检测服务
```

### 1.3 提交规范

- 提交信息使用中文描述，简洁明了
- 每次提交只做一件事
- 先 `git pull --rebase`，再 `git push`
- PR 需要至少 1 人 review 后合并

### 1.4 代码审查要点

- 是否符合命名规范
- 是否有硬编码/调试代码
- 错误处理是否完整
- 是否有安全漏洞
- 测试用例是否覆盖

## 二、命名与编码约定

### 2.1 命名规范（团队统一）

| 类型       | 规范                  | 示例                            |
| ---------- | --------------------- | ------------------------------- |
| 数据库表   | snake_case            | `inspection_record`             |
| 数据库字段 | snake_case            | `pipeline_id`, `created_at`     |
| Java 类    | PascalCase            | `PipelineController`            |
| Java 字段  | camelCase             | `pipelineId`                    |
| API 路径   | kebab 或复数资源      | `/api/pipelines`, `/api/alerts` |
| JSON 字段  | camelCase             | `pipelineId`, `severityLevel`   |
| 枚举值     | 小写 snake 或固定常量 | `pending`, `crack`, `admin`     |
| Vue 组件   | PascalCase 文件名     | `GisMap.vue`                    |
| 前端变量   | camelCase             | `defectList`                    |
| 常量       | UPPER_SNAKE_CASE      | `MAX_FILE_SIZE`                 |

### 2.2 代码格式

- Java：使用 IDEA/Eclipse 默认格式化
- TypeScript/Vue：使用 ESLint + Prettier
- Python：遵循 PEP 8

## 三、日志规范

### 3.1 日志级别使用

| 级别  | 使用场景                         |
| ----- | -------------------------------- |
| ERROR | 异常、错误、需要立即处理的问题   |
| WARN  | 潜在问题、性能警告               |
| INFO  | 关键业务节点、接口调用、系统启动 |
| DEBUG | 开发调试信息（生产环境关闭）     |

### 3.2 操作日志要求

以下操作**必须**记录 `operation_log`：

- 用户登录/登出
- 管线/图像数据导入
- 模拟数据生成
- 报告生成
- 预警规则变更
- 用户管理（增删改）

**日志内容应包含**：操作人、操作时间、操作类型、目标资源、结果

## 四、安全规范

### 4.1 密码与认证

- 密码必须 BCrypt 加密存储
- 禁止在代码/日志中明文存储密码
- JWT Token 禁止出现在 URL 参数中

### 4.2 文件上传

- 限制文件类型：`jpg`, `jpeg`, `png`, `bmp`
- 单文件 ≤ 20MB，ZIP ≤ 200MB
- 文件名 UUID 化，防止路径穿越攻击

### 4.3 SQL 与注入

- 使用 MyBatis 参数化查询
- 禁止字符串拼接 SQL
- 禁止将用户输入直接作为 SQL 条件

### 4.4 敏感信息

- 禁止提交 `.env`、密码文件到 Git
- 使用环境变量或配置文件管理敏感配置
- 生产环境信息禁止出现在错误提示中

## 五、协作流程

### 5.1 开发流程

```
1. 从 main 创建功能分支
2. 在分支开发并自测
3. 提交 PR 并指定 Reviewer
4. Review 通过后合并到 main
5. 删除已合并的分支
```

### 5.2 冲突处理

- 优先使用 `git rebase` 保持历史整洁
- 解决冲突后确保代码能正常编译运行
- 冲突解决后需重新通过 CI

### 5.3 上线流程

- 生产环境使用 `git tag` 打版本
- 上线前在测试环境充分验证
- 保留回滚方案

## 六、数据库连接规范

### 6.1 数据库配置信息

本项目使用集中式数据库共享开发模式，所有成员连接同一数据库。

| 配置项          | 值                                  |
| --------------- | ----------------------------------- |
| 数据库类型      | PostgreSQL + PostGIS                |
| 数据库名称      | `upids`                             |
| 开发账号        | `upids` / `upids123`                |
| 管理员账号      | `upids_admin` / `upids_admin_123`   |
| PostgreSQL 端口 | `5432`                              |
| Redis 端口      | `6379`                              |
| 数据库服务器 IP | 由管理员提供（如 `192.168.31.100`） |
| 空间坐标系      | WGS84（EPSG:4326）                  |

### 6.2 Docker 启动数据库

数据库管理员负责启动数据库服务：

```bash
# 启动所有服务
docker-compose up -d

# 查看日志
docker-compose logs -f

# 停止服务
docker-compose down
```

### 6.3 Spring Boot 连接配置

`backend/src/main/resources/application-dev.yml`：

```yaml
server:
  port: 8080

spring:
  datasource:
    url: jdbc:postgresql://192.168.31.100:5432/upids
    username: upids
    password: upids123
    driver-class-name: org.postgresql.Driver
  redis:
    host: 192.168.31.100
    port: 6379

upids:
  jwt:
    secret: ${JWT_SECRET:change-me-in-production}
    expire-hours: 24
  python:
    base-url: http://localhost:5000
  upload:
    path: ./uploads
  alert:
    severity-threshold: 4
```

将 `192.168.31.100` 替换为数据库服务器实际 IP。

### 6.4 Python 连接配置

```python
import psycopg2

DATABASE_URL = "postgresql://upids:upids123@192.168.31.100:5432/upids"

conn = psycopg2.connect(DATABASE_URL)
cursor = conn.cursor()
```

### 6.5 pgAdmin 连接配置

| 配置项   | 值               |
| -------- | ---------------- |
| Host     | `192.168.31.100` |
| Port     | `5432`           |
| Database | `upids`          |
| Username | `upids`          |
| Password | `upids123`       |

pgAdmin 访问地址：`http://192.168.31.100:5050`

### 6.6 权限规则

所有成员使用 `upids` 账号进行开发，该账号拥有以下权限：

**允许：**

- 查询数据
- 新增测试数据
- 修改数据
- 删除测试数据

**禁止：**

- 删除数据库
- 修改表结构
- 删除表/索引
- 修改 PostGIS 扩展配置

表结构变更由数据库管理员统一处理。

### 6.7 数据库迁移

所有数据库结构变更必须通过版本化 SQL 文件管理：

```
sql/
├── init.sql              # 初始化（PostGIS 扩展）
├── schema.sql            # 表结构 DDL
├── init_data.sql         # 初始数据
└── migrations/           # 版本化迁移脚本
    ├── V1__init.sql
    ├── V2__add_pipeline_table.sql
    └── ...
```

迁移流程：

1. 数据库管理员编写迁移 SQL 文件
2. 提交到 GitHub
3. 所有人 pull 最新代码
4. 数据库管理员执行迁移脚本
5. 通知团队成员

## 七、文档规范

### 7.1 代码注释

- 公共方法、复杂业务逻辑需要 Javadoc/TSDoc
- 注释说明「为什么」，而非「是什么」
- 及时清理无用的注释代码

### 7.2 接口文档

- 新增接口必须同步更新接口文档
- 文档路径：`docs/接口文档.md`
- 包含：路径、参数、响应、错误码

### 7.3 README

- 项目根目录 `README.md` 包含：
  - 项目简介
  - 技术栈
  - 本地启动步骤
  - 环境变量说明
