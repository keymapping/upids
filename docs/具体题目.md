# 7. 水下管线检测与缺陷识别系统

## 1. 系统背景

本系统用于黄河水域及沿岸水下管线的运行状态监测，主要替代传统人工巡检模式，实现管线结构数据的数字化管理与缺陷自动识别。系统面向水利工程管理单位，解决管线分布复杂、巡检成本高、缺陷发现滞后的问题。

---

## 2. 功能架构

系统运行采用 **"数据驱动 + GIS 空间建模 + 图像识别融合"** 的结构，整体分为四层：

| 层级         | 功能说明                                    |
| ------------ | ------------------------------------------- |
| 数据接入层   | 管线 GIS 数据 + 检测图像上传接口，REST 方式 |
| 数据治理层   | 坐标统一 + 数据去重 + 空间拓扑构建          |
| 缺陷分析层   | 规则检测 + 图像 AI 识别双通道               |
| 可视化应用层 | GIS 地图 + 缺陷标注 + 统计报表              |

系统采用 **"异步处理模式"**，图像识别任务进入消息队列后由后端批处理执行。

---

## 3. 核心业务流程

系统运行流程分为 8 个严格步骤：

1. 用户上传管线 GIS 数据（GeoJSON 或 Excel）
2. 系统进行坐标系转换（WGS84 统一）
3. 构建管线拓扑关系（节点-边结构）
4. 上传巡检图像（压缩包或单文件）
5. 图像进入队列（Kafka 或内存队列模拟）
6. Python 识别服务执行裂缝/破损检测
7. 检测结果回写 Java 后端数据库
8. GIS 端渲染缺陷点并生成风险报告

> 每一步均需记录日志以支持审计追踪。

---

## 4. 数据设计

系统数据包括三类核心表：

### （1）管线基础表

| 字段              | 说明       |
| ----------------- | ---------- |
| `pipeline_id`     | 主键       |
| `geo_coordinates` | 空间坐标   |
| `material_type`   | 材质       |
| `diameter`        | 管径（mm） |
| `install_time`    | 安装时间   |

### （2）检测记录表

| 字段               | 说明     |
| ------------------ | -------- |
| `record_id`        | 主键     |
| `pipeline_id`      | 关联管线 |
| `image_path`       | 图像路径 |
| `detection_result` | 检测结果 |
| `confidence_score` | 置信度   |
| `timestamp`        | 时间戳   |

### （3）缺陷标注表

| 字段             | 说明                       |
| ---------------- | -------------------------- |
| `defect_id`      | 主键                       |
| `defect_type`    | 缺陷类型（裂缝/腐蚀/断裂） |
| `severity_level` | 严重等级（1-5 级）         |
| `location`       | 缺陷位置                   |

### 数据规模要求

| 数据类型 | 规模要求              |
| -------- | --------------------- |
| 管线节点 | 1,000 - 20,000        |
| 图像数据 | 每日 1,000 - 5,000 张 |
| 历史记录 | ≥ 3 年                |

---

## 5. 技术实现约束

### 后端架构

- 采用 Spring Boot 分层架构（Controller-Service-DAO）
- 图像识别服务采用 Python Flask 独立部署，通过 HTTP 接口调用
- 数据库采用 PostgreSQL + PostGIS 存储空间数据
- Redis 用于缓存高频 GIS 查询结果

### 前端架构

- 采用 Vue3 + Element Plus + Leaflet 实现 GIS 地图渲染
- 缺陷点采用图层叠加方式展示
- 系统需实现文件异步上传机制
- 支持任务状态查询接口（`pending` / `running` / `done`）

---

## 6. 可扩展能力

- 系统可扩展接入深度学习检测模型（如 YOLOv8 或 Mask R-CNN），替换当前规则+基础模型混合识别模块
- 同时可扩展为"管线数字孪生系统"，实现实时状态映射与预测性维护功能
